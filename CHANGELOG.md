# Changelog

Every artifact (the Rust crates, the Swift package and both Maven artifacts) shares one version. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html), with breaking changes in a major version from 0.1.0 on.

## [Unreleased]

### Added

- `craftbridge-core`'s preview surface: it configures the app's surface from the core's device (the platform's non-sRGB format, `Fifo` with one frame in flight, and `PostMultiplied` alpha where the surface offers it, else an opaque picture, as on Android), draws a display frame into it aspect-fit between black bars, configures it again on a resize, and answers a `Gpu` error, never a panic, when the surface is outdated or lost or the device refuses a frame.
- The gate reads Rust with `syn`: `unsafe` and lint attributes are found as the syntax tree holds them (a macro's body too), an unparsable file is reported by name, and `allow(warnings)`, an allowed default clippy group and `rustfmt::skip` on a crate or module fail `rules: lints`; the hand-written source stripper is gone.
- The repository: its rules in `AGENTS.md`, the licences, and the plan of record in `plan/`.
- `tools/doctor.sh`: checks every prerequisite of the build and prints the fix for each gap; `--gate` checks only what the gate needs.
- The workspace skeleton (the Cargo workspace in `rust/`, the Swift package in `ios/sdk/`, the Gradle build in `android/sdk/`) and the gate, `tools/ci.sh`: formatters, linters, tests, `cargo xtask rules`, `cargo xtask generate --check` and `cargo xtask plan-views --check`, which rebuilds the plan's views from their sources and fails on any byte that differs bar the drawing in each diagram's SVG export; `tools/doctor.sh --install-hooks` runs it before every push.
- The EffectCraft pin: `tools/update-upstream.sh` is the one way it moves, fetching an official `storytold/effectcraft` revision and writing the `[workspace.dependencies]` pins, the `[patch]` tables, the release profile and the starting `Cargo.lock` from that revision itself; `tools/adaptations.toml` lists every adaptation and the EffectCraft items it relies on; the `upstream` rule refuses a pin that is not a commit of official EffectCraft main, a hand-written patch, and any registry, fork, path or other-commit copy of a pinned crate, and no Cargo configuration Cargo reads for a build in `rust/` — the repository's own, those in every folder above the checkout, the cargo home's, whatever those `include`, and the environment the gate runs in — may hold a `[patch]`, `paths` or a `[source]` replacement.
- Kotlin checks in the gate: detekt reads the never-crash bans (§3) over each module's shipped code, and the JNI confinement (§4), the package rule (§9) and the refusal of suppressions — over a whole file, or on an item for a rule the gate enforces (§10) — over its tests too, from Kotlin's own syntax tree with its types resolved; hand-written Java in the Android SDK is refused by the layout check; and the licence check reads the detekt tooling the gate runs as it reads what ships.
- More Android checks in the gate: Android Lint keeps `AndroidGradlePluginVersion` and `GradleDependency` switched off, because those report a newer AGP, Gradle or library by the day rather than by the change, and newer releases are looked for in the upstream update loop instead (§10); a module is refused when it keeps Kotlin or Java under its `src` in a folder none of its compilations reads — `src/testRelease/kotlin`, which AGP 9 compiles for no library, a misspelt folder, or a `.kt` left among the resources — so no file is formatted yet never compiled (§3); and a module's Gradle tasks take turns at its build folder, so that when a module loses its last sources two tasks skipped as empty cannot prune the same half-deleted folder at once and fail a gate run now and then on a correct tree.
- `craftbridge-effects-codegen surface`: the EffectCraft API surface at the pin (every command with its keys typed by the plan's type rules, and the tool catalogue), written to `generated/api-surface.json` by `cargo xtask generate`, which the gate regenerates and compares.
- `craftbridge-core`: `Folders` and `Confinement` — the container and bundle read roots and the container write root an engine starts with, prepared for it — and `CraftError`, the one error every call over the native boundary fails with, with the plan's whole mapping of failures onto it.
- `craftbridge-core`'s engine actor: the `CraftApp` trait an app plugin implements, one engine thread per engine answering its calls in order over oneshot channels, a panic inside any call answered as `Internal` with the session kept serving, and closing or dropping an engine ending its session and joining its thread.
- `craftbridge-media`: `register(on)` puts CraftBridge's decoder factory in FilmCraft's decoder registry and sets the hardware-decoding switch, and `Fallback<D>` wraps a hardware decoder so that, on an error or an in-band parameter change, the stream continues in FilmCraft's software decoder from the last random-access sample (the one before it after an HEVC CRA) without skipping or repeating a picture.
- `craftbridge-media`'s VideoToolbox decoder: on iOS, H.264, HEVC and, where the device decodes it, AV1 (4:2:0, 8-bit and 10-bit) are decoded by the hardware and returned in exactly the frame layout FilmCraft's software decoder produces, wrapped in `Fallback`; where there is no hardware decoder, such as the iOS Simulator, the factory declines and the software decoder takes the stream.
- `craftbridge-effects-codegen swift`: the Swift facade of every EffectCraft command, one file for each command namespace in `ios/sdk/Sources/CraftBridgeEffects/Generated/` (`engine.layer.newText(…)`, `engine.layer.mask.motionBlur(…)`), each enum key a value type with a static member for each word (`mode: .sameAsLayer`), so a word EffectCraft adds later breaks no `switch`; written by `cargo xtask generate` and compiled in the gate; with the minimum hand-written Swift it names (`EffectsEngine`, `JSONValue`, `Vec2`, `Vec3`, `CraftColor`, `ItemReference`).
- `craftbridge-effects-codegen diff <old> <new>`: lists the commands, keys and tools that were added, removed or changed between two API surfaces, and exits 2 when a change would break an app written against the old facade (a removed command, key, enum word or tool an app can call; a key of another type, in another place, or whose whole word list appears or goes; a key that is new and required or became required; a tool that became bridge-only or takes its input differently), 0 when none does, 1 when a file cannot be read or parsed, or the report cannot be written.
- `craftbridge-core`'s export waiting (L3): `CraftApp::request_with_progress` runs an export that reports progress once every `PROGRESS_INTERVAL`, the CLI's 100 ms, and stops when its progress closure answers `false` (an app with no such request keeps the default, which answers `Unsupported`); while `Engine::request_with_progress` runs, every other call waits behind it in the order it was made and `info` is answered from the state the export began with; a `CancelToken` stops the export at its next progress report and the call answers `Cancelled`; a `close` stops the export running and every export waiting, as a cancel does, before joining its thread; and a progress listener that fails is ignored so the export continues.
- `craftbridge-core`'s GPU device: `GpuDevice::request` makes the wgpu device itself — Metal on iOS, Vulkan on Android, the host's on the desktop, GL never — asking `wgpu::Limits::default()` clamped to the adapter, with `max_texture_dimension_2d` capped at 16384 and `max_buffer_size` from the adapter as the compositor takes those two, so a device that offers less than the defaults still answers; it gives `(adapter, device, queue)` for the compositor to render on, and when the app chose `GpuChoice::CpuOnly`, no adapter answered, or the request failed, it answers why in words `info.gpu` can report while every render runs on the CPU.
- The conformance runner: `conformance/effects/corpus.toml` holds the scenarios, `tools/oracle.sh` builds the official EffectCraft command line at the pin as their oracle, `craftbridge-effects-conformance` runs each scenario against it and compares the values it prints and the files it writes, with the 40 dB PSNR of D-12 for encoded exports, and the gate's `conformance` stage runs it.
- `craftbridge-effects`: the EffectCraft plugin answers `info`, `commands`, `exec` and `run` over its own session, built from the app's `Folders` and confined to them from its first command, with no helper process and no plug-ins unless the app names a plug-in folder; every answer and error comes in the EffectCraft command line's own shapes and words. What the confined session withholds (helpers, scripts) and the model downloads, which would start the system `curl`, answer `Unsupported` on every path, so the session starts no process; any other name `request` is given answers `Unsupported`, naming what was asked and the methods `request` answers.
- `craftbridge-core`'s frame formats: `FrameBytes` and `PixelFormat`, with PNG bytes passed through, straight RGBA kept as it is, and straight RGBA swizzled and premultiplied in place into the BGRA an iOS `CVPixelBuffer` takes, rounded as Apple's own premultiply rounds; a raw buffer whose length is not its size, a side of zero, and a size no buffer can hold are refused as `InvalidParams`, naming the sizes.
- `craftbridge-effects-codegen version`: the engine's version and the full commit of its pin, the constants the plugin's `info` reports as `version` and `pin`, in `rust/effects/craftbridge-effects/src/generated/version.rs`, written by `cargo xtask generate`, which the gate regenerates and compares; so `info`'s `pin` is the commit the workspace builds, in full however `rust/Cargo.toml` spells the pin, and moves with the pin.
- `craftbridge-core`'s `frame` call: `CraftApp::frame` and `Engine::frame` render one frame as PNG, straight RGBA or premultiplied BGRA, answered as `FrameBytes` on the engine thread in the order the calls were made, waiting behind a running export, with `Unsupported` for an app that renders none; and `craftbridge-effects` answers it from a `FrameRequest` (`comp`, `time` or `frame`, `maxSide` or `scale`, `transparent`) resolved as the command line's `render-frame` resolves its flags: its PNG is byte for byte the file `render-frame` writes, and its raw pixels are the ones that file decodes to. A missing comp answers `NotFound` in the command line's words whatever the format, and a request naming both `time` and `frame`, or both `maxSide` and `scale`, which `render-frame`'s usage gives as alternatives, answers `InvalidParams`. `request` still refuses the name `frame`, whose pixels cannot come back through JSON.
- `craftbridge-effects`: the plugin answers `props`, `get`, `set`, `open`, `save`, `saveAs` and `new`. The first three go through the tools the command line's commands of those names call, with a comp or layer given as the command line reads it (an id, a name, `#n`, or `-` for the active comp); the others run `file.open`, `file.save`, `file.saveAs` and `file.newProject`, whose results they answer, inside the folders the confinement allows (the container, and the bundle for reading) and refused by the confinement's own check outside them. `props`'s `depth` is the whole number of group levels the tool expands, as the command line's `mcp` passes it. A file the disk will not read or write — missing, unreadable, unwritable, or a full disk — answers `Io` through these methods, and through `exec` and `run` wherever the engine reports it as a file it cannot read or write.
- `craftbridge-effects`: `export` runs through the core's `request_with_progress`: `RenderRequest` has one field for each flag of the EffectCraft command line's `render`, mapped to the render-queue parameters with the command line's names, defaults and errors; the render runner unqueues the project's other items, queues the request (or renders the project's own queue with `queue`), polls the render at each progress report, stops it on the first `false` and waits for the exporter to remove what it had written, so a cancelled export leaves no output. A parameter `export` does not take, or one of the wrong kind, is refused by its name, as every method refuses its own; an export format the build lacks answers `Unsupported`, under `export` and from any command that refuses one. Any other name `request_with_progress` is given answers `Unsupported`, naming the methods it answers.
- `craftbridge-core`'s pending-export journal: `Engine::start_in(folders, app)` prepares the folders, deletes each file `pending-exports.json` (in the config folder) still lists that an export killed mid-way wrote, leaves a listed file the export never reached as it was, clears the journal and reports what it did as `Engine::recovery()`. `CraftApp::request_with_progress` gains `list_outputs`, through which an export lists every file it is about to write before it writes the first (every file of an image sequence included), and the engine clears the list when the export ends whatever its outcome. Entries are stored below the container, so a container that moved is still cleaned; every write is a temporary file renamed into place; only regular files inside the container are ever deleted, never a folder, a link or what it points at; a journal whose content is damaged deletes nothing and is replaced, and one the disk will not read when a process takes the journal is set aside unread for a later start (at most 8 at once), never failing the start or an export. A process holds an exclusive lock on `pending-exports.lock` while a start of its own deals with the journal and while its exports run, and writes the journal from what it knows meanwhile, so a journal the disk stops reading mid-run is replaced whole; a start that finds another process holding the lock deletes nothing and a listing that does is refused, each trying again next time, and an idle process holds no lock, which iOS would terminate a suspended app for.
- `craftbridge-effects`: `replay` runs a JSON-lines repro script through EffectCraft's own replay and answers its report, after checking every line against the confinement and the model-download door so a refused script runs nothing; `timings` answers the command line's `bench` as a document (per-layer and per-effect time, playback frames with and without the layer cache, and with `gpu` the CPU against an attached GPU), at a scale up to Full; `CraftApp::mcp` and `Engine::mcp` answer one line of EffectCraft's MCP transport on the session the methods act on, with the model downloads refused there too. `script` stays unanswered.

### Changed

- `tools/hooks/pre-push` gates each commit a push carries, checked out into a temporary worktree of its own, instead of the working tree the push comes from: an edit that is not part of the push neither passes nor fails it. Each gated tree gets the plan kit's dependencies from `npm ci`, as `plan/package-lock.json` pins them. A commit whose `tools/ci.sh` is gone or cannot run is refused. A repository's pushes gate one at a time, in one build folder kept warm from push to push.
