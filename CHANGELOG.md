# Changelog

Every artifact (the Rust crates, the Swift package and both Maven artifacts) shares one version. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html), with breaking changes in a major version from 0.1.0 on.

## [Unreleased]

### Fixed

- The media crate's tests on Android no longer end with `FORTIFY: pthread_mutex_lock called on a destroyed mutex` after the last test has passed. The thread that did it is the codec stack's own, the invalidator thread of the platform's buffer pool library (`libstagefright_bufferpool@2.0.so` on the API 29 emulator; the acceptance phone's two buffer pool libraries keep the same thread), which the first codec a process makes starts and nothing in the NDK ends; `exit` destroys the library's static mutex under it, in about one process in twelve on that emulator that ends right after closing a decoder. The test binary now defines `exit` itself, which ends the process at once with the status it is given, so no static is destroyed and the harness's verdict stands however a test failed. A test starts the binary a hundred times on one closed decoder and refuses a run whose output says so, since the platform's abort follows the process's own exit and its status stays 0, and another holds a test that fails after closing a decoder, by a panic or by one of the two ways that make none, to the harness's failure status.
- The Swift suite on the iOS Simulator no longer fails a second run started by hand on the same simulator, and no longer leaves folders on it: every engine but the ones under test for the app's own folders starts in a `Folders.isolated()` container of its run's own in the temporary folder, which the run holds with an exclusive lock while it may use it; each suite removes the folders it made there when its last test has run, and each new folder is made after a sweep that removes the folders no live run holds, which a run killed before its suites ended leaves; and the one suite that keeps starting in `.appDefault` — `FoldersTests`, where that default itself is what is tested — runs one test at a time and keeps an exclusive lock on the app's own folder while it does, waiting for any other run of the suite to leave those folders, so two runs of the whole suite at once on one simulator now both pass and a run leaves nothing behind.
- `craftbridge-core`'s pending-export journal no longer tells two paths apart by their spelling: every comparison — a listing's refusal, a take-over, a start's claims on files and folders another export still runs, what a set-aside entry yields to, and the folding of one folder's duplicate entries — asks whether two paths name one file the way the volume holding them decides, reading that answer from the volume rather than assuming it from the platform: one file is one device and one file number where it exists, and where it does not, the deepest folder that does plus the names below it folded by that volume's own rules — by Unicode's full case folding where it folds case, so `straße` and `STRASSE` are one name as they are on a Mac's disk, and decomposed where it folds Unicode form — while the rules read from the journal's volume fold the names on that volume alone, and a volume whose rules were not read folds every name, so it loses no work. Two exports of one file spelt two ways — other case, another Unicode form — are therefore refused, taken over, claimed and yielded exactly as one spelt one way on a volume that folds them, and on a volume that keeps the spellings apart `Card.mp4` and `CARD.MP4` stay two files, both exports running and each end removing only its own.
- `craftbridge-core`'s pending-export journal no longer lets one export delete a file another export finished at the same path: each entry names the export that listed it, an export's end clears exactly its own entries, and a path another of the app's exports has listed and not ended answers `Io` in words naming the file when a second export lists it, since two exports writing one path at once leave no defined file there and a finished file must never go by another export's cancel, kill or failure, at the time or after a restart; a journal written without the numbers still reads, its entries belonging to no export running now.
- The MediaCodec decoder no longer shows the wrong window of a stream whose crop starts off the coded picture's corner: it takes the window from the decoded image's own crop rectangle only where that is the stream's own corner, and a decoder that describes such a picture at the origin, as the Android 14 emulator's H.264 hardware decoder does, is refused with the reason named, so the software decoder gives the stream's pictures.
- `craftbridge-core`'s pending-export journal no longer refuses an export, or has a start deal with nothing, because another process holds `pending-exports.lock` when no other process uses the container. A process the app starts from any thread keeps a copy of every handle the app has open until it runs its program, the lock's among them, and the lock belongs to the open file those copies share, so the engine now unlocks it before it closes its handle, where the close alone left the lock held by that copy.

### Added

- The android stage now counts its tests written against run. A verifier task finalizes every module's unit test task and the detekt rules' own test task: the written side reads the test task's compiled test classes themselves, through the classpath the run stood on — a `@Test` in the bytecode, on the method, or on the class or a class above it, as TestNG reads it, over each public method the class declares but TestNG's configuration methods, one returning a value among them, which TestNG drops unrun — so there is no hand-kept list; the run side reads TestNG's own report file, `testng-results.xml`, which the build now makes every test run write through TestNG's own `XMLReporter` (one TestNG to a report, so the run stays one worker). Every test the build compiles that TestNG reported no run for fails the stage by name — a method-level `@Test` on an abstract base whose subclasses carry no TestNG annotation of their own among them, since Gradle hands TestNG no such subclass, and one TestNG skipped for a failed dependency or configuration answers not run with TestNG's own reason — as does every run test no compiled class marks as a test, and when the counts close the stage prints, for each module and for the rules' tests, how many tests were written and how many ran. The count reads only a report its test task left in the same build, run, found up to date or taken from Gradle's cache, and refuses to read one an earlier run left when the task is not in the build (`android/sdk/build-logic/shared`, the one build both sides of build-logic load, renamed from `licence-listing` since it now holds the count beside the licence listing, wired once by the convention plugin and by `:detekt-rules`'s own build).

- A hardware H.264 export whose encoder session is lost part way, as VideoToolbox's is when the app goes to the background (-12903), goes on in the software encoder from the first frame the hardware made no packet for, at the same settings, so the movie finishes with every frame once and in order; the software encoder's parameter sets are renamed beside the hardware's and every one is in the movie's `avcC`, under the higher profile and level of the two encoders, so a player that seeks back over the switch still shows the pictures before it. - An export whose frame the device's memory cannot hold is now refused before it renders or writes anything, in words naming the frame's size, the compositor it renders on and the memory available: a phone asked to render a frame larger than its free memory ends the app mid-render rather than finishing it, so an 8K export on a phone with a little over 450 megabytes free answers the refusal and the app keeps working, while every export the phone can hold runs as before. A frame in flight is counted at four times its bytes on the CPU and ten on the GPU, more than a one-frame export of any format measured was found to hold, and the export pool sizes itself from the same need. The memory is the platform's own figure: `os_proc_available_memory` on an iPhone, `MemAvailable` on Android and Linux, and on a Mac and in the iOS Simulator the share of the host's memory its kernel counts as available; a figure that cannot be read fails the export with its reason, and an export of sound alone, which renders no frame, is held to nothing.

- A `@Test` TestNG never runs no longer passes the gate unseen. TestNG builds a class's tests as it reads the class and drops in silence, in no report and not even as a skip, every test whose JVM method is not `void` — a body bounded to a value, as `= runBlocking { … }` is; a `Nothing` one, which compiles to a method returning `java.lang.Void`; a `Unit?` one, which compiles to one returning `kotlin.Unit`; a `suspend` one, which compiles to one returning `Object` and which the Kotlin compiler refuses only under kotlin-test's spelling of `Test`; and a property's getter —, every test whose own `@Test` sits beside an `@Ignore` or that is held in a class annotated `@Ignore`, every test saying `enabled = false`, and every one saying an `invocationCount` below one.
