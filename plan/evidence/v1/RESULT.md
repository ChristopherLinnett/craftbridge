## Verdict

- **Simulator: the listing and reads work, but they say nothing about iOS.** The app lists `/System/Library/Fonts` (82 files plus `Supplemental/` with 290 more) and reads `.ttc`, `.ttf` and `.otf` files without errors. Those are the **Mac's** fonts, though. In the simulator the app's file paths land on the Mac's file system, and no iOS sandbox limits what it can read: it also reads a plain file in the Mac's `/tmp`. So the simulator cannot show what an iPhone's sandbox allows, or what is in an iPhone's font folder.
- **CoreText in the same app reports the iOS fonts, and the app can read every one of their files.** `CTFontCollectionCreateFromAvailableFonts` returns 303 faces in 103 files, all under the iOS 26.5 runtime root. None are under the Mac's folder. All 103 files are readable. Seven of the eight folders holding them are inside `Fonts/`. The eighth is `/System/Library/PrivateFrameworks/FontServices.framework/CorePrivate`, which holds `PingFangUI.ttc`, the font iOS draws Chinese with.
- **AD2 on iOS should get its folders from CoreText, not hard-code `/System/Library/Fonts`.** EffectCraft's own `DirectorySource`, linked into the app and run on CoreText's folders, registers 633 faces from 263 files. That covers every family `UIFont.familyNames` lists (86, PingFang SC/TC/HK/MO included), and more: the walk takes every font file in those folders, while CoreText offers the app only 103 of the 263. So EffectCraft lists 311 system families where UIKit lists 86. The same call on a hard-coded `/System/Library/Fonts` registers the **Mac's** 378 families in the simulator. On the iOS layout it drops PingFang and adds Watch-only fonts.
- **Chinese text cannot use the iOS system font with either choice.** iOS draws Chinese with PingFang: CoreText's own fallback from the system UI font picks PingFang SC for 汉 and PingFang TC for 漢, both in `PingFangUI.ttc`. PingFang SC and TC are also the only families on EffectCraft's Chinese fallback lists that iOS has. PingFang stores its outlines in Apple's `hvgl` table, with no `glyf`, `CFF ` or `CFF2`, and its 32 faces are the only ones of the runtime's 645 in that format. EffectCraft 10376058 reads outlines with skrifa 0.44.0, which has no `hvgl` reader, so it cannot draw them (`has_char('汉')` is false), and its search of every installed face finds nothing else that draws Simplified 汉. So in the simulator, EffectCraft has no font for Simplified 汉 (missing-glyph box) and draws Traditional 漢 with Hiragino Sans (Japanese glyph forms), whichever folders AD2 passes. Chinese needs a bundled CJK font in `Folders.fonts`; §4 proposes one.
- **The acceptance iPhone confirms it (§7).** On "SeaEl iPhone" (iPhone 12 Pro, iOS 26.6.1), the iOS sandbox lets the app read every font file CoreText reports: 103 files in the same 8 folders, `OK 103, FAIL 0`. `DirectorySource` on those folders registers the same 633 faces from 263 files in 311 families as in the simulator, all 86 `UIFont.familyNames` families are in `families()`, and the fallback answers for 汉, 漢 and 한 are the simulator's. The face-by-face listing filter gives the same 86 families there, measured on the phone. On the device, `/System/Library/Fonts` is the iPhone's own folder (613 faces, 264 files, 296 families), which still misses `CorePrivate`.

## 2. What the probe does

The probe runs once at launch, inside `FontProbeApp.init()`. Each line of the report goes to stdout as soon as it is written. When the run ends, the full report is written to `Documents/fontprobe_report.txt` and read back. os_log gets one pointer line, because it cut the build round's whole-report messages off after about 1 KB (`capture/oslog-run2.txt`). Sections:

1. Path provenance: `realpath`, the `st_dev` of the app's `/System/Library/Fonts` against the runtime root's copy, and the process environment.
2. to 5. The worker's original checks: list `/System/Library/Fonts` and its subfolders one level deep, count files by extension, and read the first 4 bytes of one `.ttc`, one `.ttf` and one `.otf`.
6. List `/System/Library/Fonts/Core`, a folder that exists only in the iOS layout.
7. Sandbox canary: read `/tmp/craftbridge-v1/capture/sandbox-canary.txt`, a file on the Mac outside every app container. A device has no such file.
8. CoreText: `CTFontCollectionCreateFromAvailableFonts` with `kCTFontURLAttribute`. Lists the files behind the fonts by folder, reads the first bytes of every file, and compares the family lists from `UIFont.familyNames`, `CTFontManagerCopyAvailableFontFamilyNames` and the collection name by name. Also records the file behind the system UI font and five named fonts, and prints every descriptor's identity (PostScript name, file, family) as a `face` line and every `UIFont.familyNames` family as a `uifamily` line, tab-separated.
9. EffectCraft: the folders `DirectorySource::system()` picks on iOS, and `DirectorySource { dirs }.faces()` for four choices of `dirs` and for each CoreText folder on its own. Then the face-by-face match FX-3's `list_fonts` rule needs (ecprobe's `facematch`, summary; §4); `add_source` on CoreText's folders; the fallback face EffectCraft picks for 汉, 漢 and 한 next to the one CoreText picks; and `families()`, which is what `list_fonts` reads, compared with `UIFont.familyNames` both ways.
10. Font data without file access: for six fonts, `CTFontCopyAvailableTables` and `CTFontCopyTable`. Rebuilds an sfnt from the tables, compares each table byte for byte with the font's file, and passes the rebuilt bytes to EffectCraft's `add_font_data`.
11. The Documents write and read-back.

**Font data without file access (section 10):**
- For all six samples, `CTFontCopyAvailableTables` and `CTFontCopyTable` return every table in the font's file, byte-identical: system UI font 22/22, Helvetica (face 0 of 6) 16/16, Georgia 20/20, PingFang SC (face 20 of 32) 21/21, Apple Color Emoji 21/21, Noteworthy 13/13.
- An sfnt rebuilt from those tables is accepted by EffectCraft's `add_font_data` in every case (for example `Helvetica/Regular` and `System Font/Regular`). CoreText itself reloads 5 of the 6. It returns 0 descriptors for the rebuilt PingFang, which EffectCraft still parses.
- This path copies each face's tables into memory (section 10's rebuild sizes): 59 MB for PingFang SC, 139 MB for Apple Color Emoji. A collection's faces share tables, and each face's copy carries the shared ones: PingFang SC's face 20 rebuilds to 58,965,676 B of the 61,080,840 B `PingFangUI.ttc`, which holds 32 faces, and Apple Color Emoji's face 0 to 139,052,436 B of the 139,284,540 B file (section 10's `file comparison` lines give each file's size). So this path's cost is per face, and for a collection one face can cost nearly the whole file; the 352 MiB the 103 files take on disk (section 8) is not a bound on it. `add_font_data` also keeps the bytes and does not deduplicate (`fonts.rs:415-422`, unlike `add_source`, which skips a family and style already present). The folder path costs no such copy: `DirectorySource` reads only the name tables when it scans (`fonts.rs:72`), reads a file when a face is first used (`fonts.rs:40`), and shares those bytes among the faces of a collection (`fonts.rs:209-212`). So the table path only makes sense as a per-font fallback if a device refuses file reads, not as the way to register all system fonts.

## 4. Answer for V1, and the recommendation for AD2

- **V1, simulator half:** the app can list and read `/System/Library/Fonts`, but in the simulator that is the Mac's folder, with no iOS sandbox involved. What does carry over to iOS: CoreText gives the iOS font files' locations, and the app can read all of those files.
- **V1, device half: confirmed.** On the acceptance iPhone the app reads all 103 files CoreText reports, and `DirectorySource` on their folders registers the same faces as in the simulator (§7).
- **AD2 on iOS:** build `dirs` from CoreText. Take `CTFontCollectionCreateFromAvailableFonts(nil)`, get each descriptor's `kCTFontURLAttribute`, take the distinct **parent folders**, and pass them to `effectcraft_text::fonts::add_source(&effectcraft_text::fonts::DirectorySource { dirs })` (the crate root re-exports only `fonts::{FaceId, Resolved, families, resolve}`, `crates/text/src/lib.rs:25`). Do not use `/System/Library/Fonts`. In the simulator this gives the iOS fonts, not the Mac's, and it covers the folders CoreText uses outside `Fonts/`. On a device it follows whatever layout CoreText reports, and the device run (§7) shows the sandbox lets the app read those files. Do not pass the file URLs, which `walk` ignores, and do not pass their common parent: that is `/System/Library`, and the walk would go through everything under it, eight folders deep.
  - The folders hold more than CoreText offers the app (263 files against 103, §3). Registering all of it gives EffectCraft's fallback the extra script fonts. What the app is then shown is the owner's decision on FX-3, stated in the bullet after the acceptance check: everything stays registered, and only the listing is filtered.
  - The fallback of rebuilding fonts from CoreText's tables (`CTFontCopyTable` → sfnt → `add_font_data`) is not needed: the device run read every file CoreText reports.
  - AD2's registration check (that the system fonts are registered at all) compares the registry with `UIFont.familyNames`: all 86 must be in `families()`, 81 by English name and the 5 Arabic fonts under their Arabic names. A hard-coded `/System/Library/Fonts` would pass a looser check in the simulator with the Mac's families. The listing check, which #113 now states, is the *Check* below.
  - **The font list (the owner's decision, FX-3, ChristopherLinnett/craftbridge#113): every face in CoreText's folders stays registered, so drawing and fallback keep all 633; `craftbridge-effects` filters the list on every app-facing call to the faces CoreText offers the app — matched face by face — plus the bundled fonts, so the families are `UIFont.familyNames` and the bundled ones. EffectCraft is not changed.** Face matching works, measured in the app in the simulator and on the iPhone (section 9's face-by-face lines; the full detail of the simulator run in `capture/review-face-matching.txt`, made by `engine-checks.sh` from the report, §5 step 2):
    - *Identity.* The kept set has three parts. (1) A face CoreText offers: its (file, PostScript name) pair is one CoreText lists. CoreText's side: each descriptor of `CTFontCollectionCreateFromAvailableFonts(nil)`, with `kCTFontURLAttribute`'s `path` and `kCTFontNameAttribute`. EffectCraft's side: each registered face, from `effectcraft_text::fonts::all_faces()` (public, `fonts.rs:534`), which is what the filter reads, with no second scan (the measurement read the same faces as each `effectcraft_text::fonts::FaceInfo` of `DirectorySource { dirs }.faces()`, `effectcraft_text::fonts::FontSource`, public, and `add_source` registered all 633 of them), with `effectcraft_text::fonts::FaceData::File`'s path and `FaceInfo.postscript`, which is the face's own name ID 6 and never made up (`crates/text/src/sfnt.rs:122`). The folders are the parents of CoreText's own URLs, so the two paths are the same strings; in the simulator every one of the 103 files has at least one matched face (the capture's residuals all sit in files whose base face matched). (2) EffectCraft's built-in faces, `FaceData::Static` with origin `"bundled"` (`fonts.rs:356-388`): Inter, JetBrains Mono and Noto Serif, 7 faces.
