## 3. Defects found in round A2, and fixes

1. **major — RESULT verdict and §3/§4: "633 faces and 311 families: the iPhone's own set" was wrong.** The walk takes every font file in CoreText's 8 folders: 263 files, while CoreText offers the app 103. EffectCraft lists 219 visible families where `UIFont.familyNames` lists 86: 133 extra, 102 of them from `UnicodeSupport` (CoreText lists 4 of its 106 files) and 31 from four other folders. Nothing in RESULT said so, and FX-3's acceptance check would have met it unprepared. **Fix:** the probe now prints, per CoreText folder, the files CoreText lists against what `DirectorySource` finds, and the 141 non-dot families UIKit lacks; RESULT's verdict, §3 (new per-folder table and bullet) and §4 describe the superset, what it is good for (EffectCraft's last-resort fallback searches every face, `fonts.rs:1169-1174`; Carlito is its Calibri stand-in), and the acceptance check in full (all 86, 5 under Arabic names).
2. **major — RESULT §5 could not be followed as written, and several captures had no recorded command.** No `cd`, `<RuntimeRoot>` placeholders inside commands, and the example builds relied on `CARGO_TARGET_DIR` being unset (with it set, `simctl spawn` would run a stale or missing binary). The two folder lists, the hvgl per-face counts, the Al Nile captures and the family difference were made by commands nobody kept. **Fix:** new `review-scripts/engine-checks.sh` makes every non-app capture from the app's report (folder lists, family lists and their difference, Arabic face names, the in-simulator fallback, outline formats) with its own `CARGO_TARGET_DIR`; `outline-formats.py` now prints the per-face counts too (B1's separate file dropped, kept in `capture/b1-run/`); §5 rewritten as six runnable steps.
3. **major — `run-sim.sh` without `pipefail`.** `xcodebuild … | grep '^\*\* BUILD'` succeeds when the build fails (grep finds `** BUILD FAILED **`), so the script went on to install and run the previous build's app. **Fix:** `set -eu -o pipefail`.
4. **minor — `run-sim.sh` raced its own copies.** It waited for `READ-BACK` in the Documents file, then copied stdout, whose last chunk the app writes after that; and a `cmp` mismatch did not stop the script. **Fix:** it waits for the `READ-BACK` line on stdout (written last), fails after 120 s without one, and `cmp` is fatal.
5. **minor — `capture/review-oslog.txt` was stale.** It held round A1's lines from the `%d` build, so nothing showed B1's `%zd` fix, and no script made it. **Fix:** `run-sim.sh` writes the run's own os_log line (by pid) into it.
6. **minor — RESULT §7: the `devicectl … --console` step never returns**, and the recipe did not say so. **Fix:** §7 says to watch for the `READ-BACK` line and press Ctrl-C (forwarded to the app, per the help text), and that Developer Mode must be on (Apple doc URL).
7. **minor — B1's exit-2 fix was incomplete.** `dirfamilies` still exited 0 with no output for an empty list, no argument or a missing folder (for example a literal `<RuntimeRoot>`); `fallback` accepted a list naming a missing folder. **Fix:** one reader, `ecprobe::folders_from_args_or_exit`, used by both: exit 2 for an unreadable list, no folder, or a path that is not a folder. Both examples take folders or `@file`.
8. **minor — duplicated code in `ecprobe`.** The folder-list parsing existed three times (`lib.rs`, `dirfamilies.rs`, `fallback.rs`) and the list-reading error handling twice. **Fix:** `folders_in` and `folders_from_args_or_exit` in `lib.rs` (crate now also an `rlib`); the fallback samples live once, in `ecprobe::fallback_faces`, used by `fallback.rs` and, through `ecprobe_fallback_faces`, by the app.
9. **minor — unsound FFI signatures.** `ecprobe_add_font_data` and `ecprobe_free` dereferenced raw pointers in safe `pub extern "C"` functions (clippy's deny-by-default `not_unsafe_ptr_arg_deref`; `cargo clippy` failed); `ecprobe_count_faces` and `ecprobe_register_dirs` did the same through a helper. **Fix:** all pointer-taking functions are `unsafe extern "C"` with `# Safety` sections; the C header and Swift calls are unchanged; `cargo clippy --all-targets` is clean for the host and the simulator target.
10. **minor — stale doc comment:** `ecprobe_register_dirs` documented its first line as "added <n>; families <m>". **Fix:** documents the real format.
11. **minor — stale comment:** `FontProbeApp.swift` said the report goes to os_log. **Fix:** stdout and Documents, os_log a pointer line.
12. **minor — repeated Swift expression:** `CTFontCopyAttribute(font, kCTFontURLAttribute) as? URL` in three places. **Fix:** one `fileURL(_:)` helper (plus `describeFont` and `systemUIFont`, each used twice).
13. **minor — `outline-formats.py` called a face undrawable when it only had `VARC` outlines**, which skrifa 0.44.0 draws (`OutlineGlyphFormat::Varc`). No runtime face is affected. **Fix:** `VARC` counted as drawable.

## 4. Agreement with the recommendation

**Agree, with one correction now in RESULT.** AD2 on iOS should take the parent folders of the files CoreText reports through `CTFontCollectionCreateFromAvailableFonts` + `kCTFontURLAttribute` and pass them to `add_source(&DirectorySource { dirs })`. A hard-coded `/System/Library/Fonts` gives the Mac's fonts in the simulator, and on the iOS layout it misses `CorePrivate` (PingFang) and adds Watch fonts. File URLs are ignored by `walk`, and the common parent is far too wide. The correction: those folders hold 2.5 times the files CoreText offers, so EffectCraft lists 133 visible families (and 92 hidden ones) that iOS does not offer apps. That is good for fallback and a display question for FX-3, not a reason to change the folder choice. A bundled CJK font is still needed for Chinese: iOS draws Chinese with PingFang, which is `hvgl`-only, and EffectCraft's fallback finds nothing else.
