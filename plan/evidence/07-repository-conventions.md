# Repository conventions: Swift, Android and Kotlin, Rust, UniFFI SDKs, house rules

> Evidence file. Facts only, each with an anchor a reader can re-check. Business choices and unknowns go to `plan.mjs q add`, never into assumptions.

## Question this file answers

What do the Swift, Android and Kotlin, and Rust ecosystems, the SDKs that already ship Rust to iOS and Android through UniFFI, and the Craft repositories' own rules expect of a repository like CraftBridge's: its layout, packaging, formatters and linters, API style and mechanical rule checks?

## Findings

All read 2026-11-12. **Unverified** marks a point no source confirmed; the build settles each one by trying it.

### Swift and Swift Package Manager

1. **SwiftPM takes a package by URL only from a repository root.** A package consumed by git URL is a repository with `Package.swift` at its root; a package in a subfolder cannot be consumed by URL (SwiftPM `Documentation/Usage.md`, mirror https://sources.debian.org/src/swiftlang/6.2.3-1/swiftpm/Documentation/Usage.md; https://forums.swift.org/t/can-i-use-a-swiftpm-package-off-the-local-filesystem-without-making-a-separate-git-repository-for-it/43581).
2. **Rust SDKs ship Swift from a distribution repository.** matrix-rust-components-swift holds only `Package.swift` (one remote binary target and a version-and-checksum pair) and the committed generated Swift; "all local development is done via the SDK's repo" (https://raw.githubusercontent.com/matrix-org/matrix-rust-components-swift/main/README.md, …/Package.swift). bitwarden/sdk-swift is the same shape (https://github.com/bitwarden/sdk-swift). Mozilla's rust-components-swift is deprecated: firefox-ios takes releases from application-services directly (https://raw.githubusercontent.com/mozilla/rust-components-swift/main/README.md).
3. **Ferrostar keeps `Package.swift` at its repository root** and points every target into `apple/Sources/…` with `path:`, including the UniFFI-generated Swift in `apple/Sources/UniFFI`; a constant `let useLocalFramework = false` switches between a local XCFramework (`path:`) and the released zip (`url:` and `checksum:`) (https://raw.githubusercontent.com/stadiamaps/ferrostar/main/Package.swift).
4. **Binary targets.** `binaryTarget(path:)` is a local XCFramework relative to the package root; `binaryTarget(url:checksum:)` is a remote zip; a consumer resolving a `path:` target whose file is missing fails with "does not contain expected binary artifact" (https://developer.apple.com/forums/thread/651187; https://forums.swift.org/t/debugging-does-not-contain-expected-binary-artifact-error/58870). The zip layout and `swift package compute-checksum`: **unverified** against https://developer.apple.com/documentation/xcode/distributing-binary-frameworks-as-swift-packages.
5. **UniFFI's Swift output** is a C header, a module map and a Swift file importing that module; `uniffi-bindgen-swift` always runs in library mode and can emit each part separately (https://mozilla.github.io/uniffi-rs/latest/swift/overview.html; https://mozilla.github.io/uniffi-rs/latest/swift/uniffi-bindgen-swift.html).
6. **Swift API Design Guidelines**: clarity at the point of use; omit needless words; call sites read as English; label arguments unless indistinguishable; defaults last; `sort()`/`sorted()` pairs; Booleans read as assertions; every declaration documented with a one-sentence summary and `Parameter`/`Returns`/`Throws` (https://www.swift.org/documentation/api-design-guidelines/).
7. **swift-format ships in the toolchain** as `swift format`, configured by `.swift-format`; `lint --strict` exits non-zero on any finding (https://github.com/swiftlang/swift-format/blob/main/README.md). Xcode 26.6 here carries swift-format 6.3.0, and its rules include `NeverForceUnwrap`, `NeverUseForceTry`, `NeverUseImplicitlyUnwrappedOptionals`, `AllPublicDeclarationsHaveDocumentation` and `ValidateDocumentationComments` (`swift format dump-configuration`, run 2026-11-12). SwiftLint is the main alternative, a separate install; Ferrostar uses it and excludes its UniFFI folder (https://github.com/realm/SwiftLint; https://raw.githubusercontent.com/stadiamaps/ferrostar/main/.swiftlint.yml).
8. **Package build for iOS.** `xcodebuild -scheme CraftBridge-Package -destination 'generic/platform=iOS Simulator' build` builds every target of a package for the simulator without a booted device (run 2026-11-12, Xcode 26.6: both modules compiled).
9. **API breaks.** `swift package diagnose-api-breaking-changes <baseline>` diffs a package's public API against a baseline revision; reported weak with C dependencies and on iOS-only packages (https://forums.swift.org/t/swift-package-diagnose-api-breaking-changes/54308; https://forums.swift.org/t/using-diagnose-api-breaking-changes-against-a-package-with-objective-c-dependencies/75847).
10. **Tests and docs.** Swift Testing (`import Testing`) coexists with XCTest, which remains for performance and UI tests (https://useyourloaf.com/blog/migrating-xctest-to-swift-testing/, secondary). DocC through `swift-docc-plugin` (https://github.com/swiftlang/swift-docc-plugin). Swift 6 language mode with `Sendable` public types: **unverified** (https://www.swift.org/migration/documentation/migrationguide/ returned no content).

### Android, Gradle and Kotlin

11. **Library modules.** `com.android.library` builds an AAR, which may carry `jni/<abi>/*.so` and consumer R8 rules; `namespace` is required; `minSdk` stays low because the manifest merger rejects a dependency with a higher one (https://developer.android.com/studio/projects/android-library; https://developer.android.com/build/publish-library/prep-lib-release).
12. **Consumer R8 rules** go in `consumerProguardFiles`; broad package-wide keep rules and global options are forbidden in library rules, which must work under R8 full mode (https://developer.android.com/topic/performance/app-optimization/library-optimization). JNA's FAQ gives broad `com.sun.jna` keep rules (https://github.com/java-native-access/jna/blob/master/www/FrequentlyAskedQuestions.md). UniFFI's Kotlin needs `net.java.dev.jna:jna:5.12.0+@aar` and kotlinx-coroutines 1.6+ (https://mozilla.github.io/uniffi-rs/latest/kotlin/gradle.html). The narrowest JNA rules: **unverified**.
13. **One definition of versions and setup.** Gradle imports `gradle/libs.versions.toml` as `libs` (https://docs.gradle.org/current/userguide/version_catalogs.html); Now in Android keeps every module's shared setup in convention plugins in an included `build-logic` build (https://github.com/android/nowinandroid).
14. **Versions.** AGP 9.5.1 needs Gradle 9.6.0+, JDK 17 and Build Tools 36.0.0 and defaults to NDK 28.2.13676358 (https://developer.android.com/studio/releases/gradle-plugin); Kotlin 2.4.21 is current (https://kotlinlang.org/docs/releases.html). Since AGP 9.0 Kotlin is built in: applying `org.jetbrains.kotlin.android` is an error and Kotlin is configured through `kotlin { compilerOptions {} }` (https://developer.android.com/build/migrate-to-built-in-kotlin). This machine has Gradle 9.6.1, NDK 28.2.13676358, Build Tools 37.0.0, JDK 21 in Android Studio and JDK 26 as the default `java` (`gradle --version`, `java -version`, 2026-11-12).
15. **The Gradle build in a platform folder.** SDKs that hold Rust as well keep the Gradle build in its own folder with its own `settings.gradle` and `gradlew`: Ferrostar `android/`, matrix-rich-text-editor `platforms/android/` (https://github.com/stadiamaps/ferrostar/tree/main/android; https://github.com/matrix-org/matrix-rich-text-editor/tree/main/platforms/android). application-services keeps Gradle at its root (https://raw.githubusercontent.com/mozilla/application-services/main/build.gradle).
16. **Publishing.** AGP's `publishing { singleVariant("release") { withSourcesJar() } }` with `maven-publish` (https://developer.android.com/build/publish-library/configure-pub-variants). GitHub Packages Maven is `https://maven.pkg.github.com/OWNER/REPOSITORY` and needs a classic token even to read public packages (https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-gradle-registry; https://docs.github.com/en/packages/working-with-a-github-packages-registry/working-with-the-apache-maven-registry). `io.github.<username>` is the Maven Central namespace a GitHub account is granted (https://central.sonatype.org/register/namespace/).
17. **Kotlin conventions**: lowercase packages, directories following packages, a file named after its single class, 4-space indent, trailing commas; libraries declare visibility and return types explicitly and document public members (https://kotlinlang.org/docs/coding-conventions.html). Explicit API mode is `kotlin { explicitApi() }` (https://kotlinlang.org/docs/api-guidelines-backward-compatibility.html). The binary-compatibility-validator is in maintenance mode and points to KGP's ABI validation, still `@ExperimentalAbiValidation` (https://github.com/Kotlin/binary-compatibility-validator; https://kotlinlang.org/docs/gradle-binary-compatibility-validation.html); support for Android library modules: **unverified**.
18. **AndroidX API guidelines**: async work as cancellable `suspend` functions; blocking work as `@WorkerThread` functions, never wrapped in `suspend`; no platform types in public APIs; no `data class`, and no `enum` or `sealed` for extensible values, in library APIs; no names ending in `Impl`; required parameters, then defaults, then a trailing lambda (https://android.googlesource.com/platform/frameworks/support/+/androidx-main/docs/api_guidelines/index.md; …/async.md; …/kotlin.md; https://android.googlesource.com/platform/developers/docs/+/refs/heads/main/api-guidelines/index.md).
19. **Formatters and analysers.** ktlint is the Kotlin conventions' checker and Now in Android runs it through Spotless; ktfmt `--kotlinlang-style` is enforced in AOSP frameworks/base; detekt 1.23.8 is built against Kotlin 2.0.21 and detekt 2.0 is still alpha; Android Lint runs as `./gradlew lint` (https://github.com/android/nowinandroid; https://github.com/facebook/ktfmt; https://android.googlesource.com/platform/frameworks/base/+/8fb6d0e0bff2; https://github.com/detekt/detekt).
20. **16 KB pages.** Apps targeting API 35+ must support 16 KB pages on 64-bit devices, and Play blocks updates that don't from 2027-02-01; NDK r28+ aligns by default; `llvm-objdump -p lib.so` shows `2**14` (https://developer.android.com/guide/practices/page-sizes).
21. **Tests.** Instrumented tests (`src/androidTest`, `connectedAndroidTest`) run the library on a device or emulator; local JVM tests cannot load an Android `.so`; Gradle Managed Devices run emulators from the build (https://developer.android.com/training/testing/local-tests; https://developer.android.com/studio/test/gradle-managed-devices).

### Rust

22. **Large workspaces**: a virtual manifest at the root; crate name equals folder name; automation in Rust through `cargo xtask`, not shell (https://matklad.github.io/2021/08/22/large-rust-workspaces.html; https://github.com/matklad/cargo-xtask).
23. **Inherited tables.** `[workspace.package]`, `[workspace.dependencies]` and `[workspace.lints]` are inherited with `.workspace = true` and `[lints] workspace = true`; edition 2024 defaults to `resolver = "3"` (https://doc.rust-lang.org/cargo/reference/workspaces.html; https://doc.rust-lang.org/cargo/reference/resolver.html). A command-line lint level such as `[lints]` gives is overridden by an `allow` attribute in the source, except a `forbid` (`evidence/05-mobile-platforms.md` Finding 7).
24. **Rust API Guidelines**: C-CASE naming, C-GOOD-ERR error types, C-SEND-SYNC, C-CRATE-DOC, C-FEATURE additive features, C-DEBUG (https://rust-lang.github.io/api-guidelines/checklist.html).
25. **cargo-deny** fails on a licence outside `licenses.allow`, on a git source missing from `sources.allow-git` (`unknown-git = "deny"`), and, with `bans.multiple-versions = "deny"`, on any duplicated crate (https://embarkstudios.github.io/cargo-deny/checks/licenses/cfg.html; https://embarkstudios.github.io/cargo-deny/checks/sources/cfg.html; https://embarkstudios.github.io/cargo-deny/checks/bans/cfg.html). matrix-rust-sdk and bitwarden allow multiple versions in general (https://raw.githubusercontent.com/matrix-org/matrix-rust-sdk/main/.deny.toml; https://raw.githubusercontent.com/bitwarden/sdk-internal/main/deny.toml).
26. **Pinning a toolchain installs it.** A `rust-toolchain.toml` naming `channel = "1.99.1"` and four mobile targets made rustup install that toolchain and `x86_64-linux-android` on first use (run 2026-11-12, rustup 1.29.2).

### Rust-to-mobile SDKs built with UniFFI

27. **mozilla/application-services**: Cargo and Gradle at the root; `components/<name>/{src,android,ios,uniffi.toml}`; `megazords/full` (`staticlib` and `cdylib`) depends on and re-exports every component so all scaffolding links into one library; generated bindings are gitignored; every component's `uniffi.toml` names one shared Swift `ffi_module_name` (https://github.com/mozilla/application-services; …/megazords/full/Cargo.toml; …/.gitignore; …/components/nimbus/uniffi.toml).
28. **matrix-org/matrix-rust-sdk**: virtual manifest; `crates/*`, `bindings/matrix-sdk-ffi` (`cdylib`, `staticlib`, `lib`), `uniffi-bindgen/` (one line, `uniffi::uniffi_bindgen_main()`), `xtask/` building the XCFramework; `default-members` leave bindings out of plain builds; layering documented in `ARCHITECTURE.md`, not checked (https://raw.githubusercontent.com/matrix-org/matrix-rust-sdk/main/Cargo.toml; …/xtask/src/swift.rs; …/ARCHITECTURE.md).
29. **Per-platform folders.** Ferrostar has `common/` (its own Cargo workspace with `[workspace.lints]` and `unsafe_code = "forbid"`), `apple/`, `android/` (its own Gradle build) and `web/`; Swift bindings are committed and Kotlin bindings generated at build time from the built `.so` (https://raw.githubusercontent.com/stadiamaps/ferrostar/main/common/Cargo.toml; …/android/core/build.gradle). matrix-rich-text-editor has Cargo at the root and `platforms/{android,ios,web}`, each its own build (https://raw.githubusercontent.com/matrix-org/matrix-rich-text-editor/main/Cargo.toml).
30. **Rules checked by code.** bitwarden/sdk-internal enforces rules with custom lints, one requiring a `uniffi.toml` beside every `setup_scaffolding!()` (https://raw.githubusercontent.com/bitwarden/sdk-internal/main/support/lints/README.md); EffectCraft checks its crate layering with `cargo xtask layers` over `cargo metadata` (`effectcraft: xtask/src/main.rs:136-166`).
31. **UniFFI manual**: library-mode generation (`generate --library`) is preferred and suits several UniFFI crates in one library; proc-macro external types work across crates; Kotlin `uniffi.toml` keys `package_name`, `cdylib_name`, `external_packages`; Swift keys `module_name`, `ffi_module_name`, `ffi_module_filename`. The manual takes no position on committing bindings (https://mozilla.github.io/uniffi-rs/latest/tutorial/foreign_language_bindings.html; …/kotlin/configuration.html; …/swift/configuration.html; …/types/remote_ext_types.html).

### The Craft repositories' rules and the owner's

32. **House rules** (`effectcraft: AGENTS.md:1-90`): never crash, with the `deny` list `clippy::unwrap_used`, `expect_used`, `panic`, `unimplemented`, `todo`, `unreachable` and `panic = "unwind"` for the last-resort guard; no `unsafe` except where the repository names an exception; the licence allowlist; guards say why; one task id per commit and only green states; `main` changes through pull requests; no agent attribution. The rules on `storytold/craft-common-actions` workflows, contributor credits, community links and `craft-fonts` govern storytold repositories.
33. **EffectCraft's dependency licences**: MIT, Apache-2.0, BSD, ISC, Zlib, Unicode, CC0, BSL-1.0, or MPL-2.0 used unmodified (`effectcraft: AGENTS.md:153-154`).
34. **The ArtCraft brand licence** lets a derived work say, in plain text, that it is based on EffectCraft by the ArtCraft team, and keeps the ArtCraft name and marks out of its name, logo and listings (`effectcraft: docs/brand/LICENSE-brand.txt:1-42`).
35. **The owner's standing rules**: no copy-paste (reuse, extend the one definition, or promote it to a shared one); code two Craft app plugins need lives in the universal core, never borrowed from a sibling Craft app; upstream wins.

## Calls the design makes into this system

None: this file describes conventions and tools, which the plan follows rather than calls.

## Consequences for the design

- One folder per platform, each a complete build, with `Package.swift` at the top of `ios/sdk/` (Findings 1, 15, 29; PD19). Because SwiftPM takes packages by URL only from a repository root, each release writes the distribution repository `ChristopherLinnett/craftbridge-swift` (Findings 1–3) → D-1, D-24.
- Rules are checked by code: `cargo xtask rules` in EffectCraft's shape plus cargo-deny (Findings 25, 30) → D-25.
- One lint table inherited by every crate, `unsafe_code = "deny"` so the UniFFI and platform crates can `allow` it where the checker permits (Findings 23, 32) → D-20, D-25.
- Formatters and linters: rustfmt and clippy, `swift format` with its "never" rules, Spotless with ktlint plus Android Lint, explicit API mode and warnings as errors (Findings 7, 17, 19) → D-25.
- Generated code committed in `generated`/`Generated` directories and checked by regeneration (Findings 3, 29, 31) → D-26.
- A workspace `uniffi-bindgen` crate instead of a global install, so the generator always matches the library's UniFFI (Finding 28) → §20, P3.
